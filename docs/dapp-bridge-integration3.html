DApp 浏览器 - Trust Wallet Provider 集成文档

本文档详细说明了在 iOS WKWebView 中集成 Trust Wallet trust-min.js 实现 DApp 与原生钱包交互的完整架构。

第一部分：EIP-1193 标准协议方法

EIP-1193 是 Ethereum Provider JavaScript API 的官方标准协议，定义了 window.ethereum 必须实现的接口。

1.1 核心方法（必须实现）

方法 签名 返回值 描述
request (args: { method: string; params: any[] }) => Promise<any> Promise<any> ✅ 推荐入口，发送 JSON-RPC 请求。现代 DApp 都使用此方法
on (eventName: string, listener: Function) => this Provider instance 添加事件监听器
off (eventName: string, listener: Function) => this Provider instance 移除事件监听器（removeListener 的别名）
removeListener (eventName: string, listener: Function) => this Provider instance 移除事件监听器

1.2 标准事件

事件 参数类型 触发时机
connect { chainId: string } 成功连接到区块链网络
disconnect { code: number; message: string } 断开网络连接
chainChanged chainId: string (hex 格式) 当前连接的链 ID 改变
accountsChanged accounts: string[] 用户选中的账户列表改变
message { type: string; data: any } 接收到通用消息

1.3 在 trust-min 中的完整调用示例

// 现代标准方式（EIP-1193）
window.ethereum
  .request({ method: 'eth_requestAccounts' })
  .then(accounts => {
    console.log('Accounts:', accounts);
  })
  .catch(error => {
    console.error('Error:', error);
  });

// 监听链变化（标准事件）
window.ethereum.on('chainChanged', (chainId) => {
  console.log('Chain changed to:', chainId);
  window.location.reload();
});

// 监听账户变化（标准事件）
window.ethereum.on('accountsChanged', (accounts) => {
  console.log('Accounts changed:', accounts);
});

第二部分：window.trustwallet 对象接口

trust-min.js 加载后会在 window 上创建 window.trustwallet 对象，暴露 Provider 构造函数供调用方使用。

2.1 所有属性和方法

成员 类型 必须由你提供 描述
Provider constructor ❌ Ethereum EIP-1193 Provider 构造函数，用于创建 window.ethereum
postMessage (name: string, id: number, object: any) => void ✅ 必须 trust-min 通过此方法发送请求到原生应用。这是核心出口
TrustSolanaWeb3Provider constructor ❌ Solana 区块链 Provider
TrustAptosWeb3Provider constructor ❌ Aptos 区块链 Provider
getKey function ❌ Cosmos 密钥获取
signAmino function ❌ Cosmos Amino 签名
signDirect function ❌ Cosmos Direct 签名
⚠️ 关键点： window.trustwallet.postMessage 必须由你实现并替换！trust-min 只定义了调用协议，实际实现需要你提供来连接原生应用。

2.2 postMessage 调用协议

当 trust-min 有请求需要发给原生时，调用格式：

window.trustwallet.postMessage(methodName, requestId, payload);

请求方法名映射关系：

DApp RPC method trust-min name
eth_requestAccounts requestAccounts
personal_sign / eth_sign signMessage
eth_signTransaction signTransaction
eth_sendTransaction sendTransaction
eth_signTypedData / v4 signTypedData

第三部分：window.ethereum Provider 对象方法

当你调用 window.ethereum = new window.trustwallet.Provider(config) 创建实例后，得到一个完整的 EIP-1193 兼容 Provider。

3.1 构造函数配置

window.ethereum = new window.trustwallet.Provider({
  isDebug: false,
  ethereum: {
    address: '',  // 当前选中的钱包地址（初始为空）
    chainId: 1    // 当前链 ID（可选）
  }
});

3.3 原生需要调用的回传方法

原生处理完请求后，必须调用这些方法把结果返回给 trust-min：

方法 签名 何时调用
sendResponse (id: number, result: any) => void ✅ 请求成功时调用，将结果返回给 trust-min
sendError (id: number, error: string \| Error) => void ✅ 请求失败时调用，将错误返回给 trust-min
💡 双向通信：
trust-min → 你（通过 window.trustwallet.postMessage）
你 → trust-min（通过 window.ethereum.sendResponse/sendError）

4.4 设计思想

这是 trust-min 设计的分层分离架构：

层次 职责 由谁提供
Provider 层 实现 EIP-1193 标准接口，协议转换 trust-min.js
桥接层 连接 JS 与原生，转发请求和响应 你的应用（glue code）
原生业务层 保存私钥、签名、用户授权、RPC 转发 你的应用（Swift）

优点：

  • ✅ 关注点分离：trust-min 只处理协议转换，不关心原生怎么实现
  • ✅ 跨平台通用：相同的 trust-min 可以在 iOS/Android/浏览器扩展 使用
  • ✅ 安全可控：私钥永远留在原生应用，不会暴露给 JS
  • ✅ 易于维护：协议固定，两边可以独立升级
