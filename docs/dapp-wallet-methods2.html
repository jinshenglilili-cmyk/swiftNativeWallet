DApp 调用钱包 - 常用方法及示例

本文档列出了 DApp 与以太坊钱包交互最常用的 JSON-RPC 方法，包含完整的调用示例，可直接复制使用。

📋 统一调用格式：
所有方法都遵循 EIP-1193 标准 window.ethereum.request(args) 格式： 
window.ethereum.request({
  method: 'method_name',
  params: [...]
})
.then(result => {
  // 处理成功结果
})
.catch(error => {
  // 用户拒绝或出错
});

概述

在 EIP-1193 标准中，DApp 通过 window.ethereum.request() 调用钱包方法，钱包返回 Promise。所有方法都可以分为两类：

类型 需要用户授权 说明
授权/签名/交易 ✅ 是 需要用户弹窗确认，会等待用户批准或拒绝
查询/只读 ❌ 否 无需用户交互，直接返回结果

一、授权相关

eth_requestAccounts 需要授权
功能：请求用户授权连接钱包，获取用户账户地址列表。这是 DApp 与钱包交互的第一步。
调用示例： 
window.ethereum.request({
  method: 'eth_requestAccounts',
  params: []
})
.then(accounts => {
  // accounts = ["0x1234...abcd"]
  console.log('用户地址:', accounts[0]);
  // 保存用户地址
  userAddress = accounts[0];
})
.catch(error => {
  console.error('用户拒绝连接', error);
});

返回结果：

string[] - 授权的账户地址数组，第一个是当前选中地址
eth_requestPermissions 需要授权
功能：请求特定权限（EIP-2255），主要用于请求账户访问权限。
调用示例： 
window.ethereum.request({
  method: 'eth_requestPermissions',
  params: [{
    eth_accounts: {}
  }]
})
.then(permissions => {
  console.log('权限已批准', permissions);
  // 权限批准后再获取账户
  return window.ethereum.request({
    method: 'eth_accounts'
  });
})
.catch(error => {
  console.error('权限被拒绝', error);
});

二、账户相关

eth_accounts 无需授权
功能：获取当前已授权的账户地址列表。如果还没授权返回空数组。
调用示例： 
window.ethereum.request({
  method: 'eth_accounts'
})
.then(accounts => {
  if (accounts.length > 0) {
    console.log('已连接: ', accounts[0]);
    currentAddress = accounts[0];
  } else {
    console.log('未连接');
  }
});

返回结果：

string[] - 已授权账户地址数组，如果未授权返回空数组
eth_coinbase 无需授权
功能：获取当前选中的 coinbase 地址（就是当前用户账户地址）。
调用示例： 
window.ethereum.request({
  method: 'eth_coinbase'
})
.then(address => {
  console.log('当前地址: ', address);
});

返回结果：

string | null - 当前地址，未连接返回 null

三、网络相关

eth_chainId 无需授权
功能：获取当前连接区块链的链 ID，返回十六进制字符串。
调用示例： 
window.ethereum.request({
  method: 'eth_chainId'
})
.then(chainIdHex => {
  const chainId = parseInt(chainIdHex, 16);
  console.log('当前链 ID: ', chainId);

  // 检查是否是正确网络
  if (chainId !== 1) {
    console.warn('请切换到以太坊主网');
  }
});

常见链 ID：

  • 以太坊主网: 0x1 → 1
  • Ropsten: 0x3 → 3
  • BSC: 0x38 → 56
  • Polygon: 0x89 → 137
  • Avalanche: 0xa86a → 43114
net_version 无需授权
功能：获取网络版本（其实就是链 ID，返回十进制字符串）。这是旧方法，推荐使用 eth_chainId。
调用示例： 
window.ethereum.request({
  method: 'net_version'
})
.then(chainIdStr => {
  const chainId = parseInt(chainIdStr, 10);
  console.log('链 ID: ', chainId);
});

四、签名相关

personal_sign 需要授权
功能：对个人消息进行签名，这是最常用的签名方法。标准参数顺序是 [message, address]。
参数：
  • params[0] - 要签名的消息（十六进制）
  • params[1] - 签名账户地址
调用示例： 
// 将要签名的消息转成十六进制
const message = 'Hello DApp! Please sign to confirm your identity.';
const messageHex = Buffer.from(message).toString('hex');
const signerAddress = '0x1234...';

window.ethereum.request({
  method: 'personal_sign',
  params: ['0x' + messageHex, signerAddress]
})
.then(signature => {
  console.log('签名结果: ', signature);
  // 将签名发送到后端验证
  return fetch('/api/verify', {
    method: 'POST',
    body: JSON.stringify({
      message, signature, address: signerAddress
    })
  });
})
.catch(error => {
  console.error('用户拒绝签名', error);
});

返回结果：

string - 65字节的签名，格式 0x...
eth_sign 需要授权
功能：对数据进行签名（旧方法，安全性有问题，现在推荐使用 personal_sign）。
调用示例： 
window.ethereum.request({
  method: 'eth_sign',
  params: [address, dataHash]
})
.then(signature => {
  console.log(signature);
});
⚠️ 不推荐使用：eth_sign 可以签名任意数据包括交易，存在安全问题，大多数钱包不再支持。请使用 personal_sign。
eth_signTypedData_v4 需要授权
功能：对结构化数据（EIP-712）进行签名，常用于签名登录、订单等结构化信息。
调用示例： 
const domain = {
  name: 'My DApp',
  version: '1',
  chainId: 1,
  verifyingContract: '0x...contractAddress...'
};

const types = {
  EIP712Domain: [
    { name: 'name', type: 'string' },
    { name: 'version', type: 'string' },
    { name: 'chainId', type: 'uint256' },
    { name: 'verifyingContract', type: 'address' }
  ],
  Order: [
    { name: 'maker', type: 'address' },
    { name: 'amount', type: 'uint256' }
  ]
};

const value = {
  maker: userAddress,
  amount: '1000000000000000000'
};

const data = JSON.stringify({
  domain, types, message: value
});

window.ethereum.request({
  method: 'eth_signTypedData_v4',
  params: [userAddress, data]
})
.then(signature => {
  console.log('签名: ', signature);
  // 发送给后端验证签名
});

五、交易相关

eth_sendTransaction 需要授权
功能：发送交易，由钱包完成签名并广播到网络。DApp 只需要构造交易，用户批准后钱包处理剩下的。
参数：
  • from - 发送者地址
  • to - 接收者地址
  • value - 转账金额（十六进制 wei）
  • gas - gas limit（可选，十六进制）
  • gasPrice - gas price（可选，十六进制）
  • data - 调用数据（可选）
调用示例（ETH 转账）： 
// 转账 0.1 ETH 到 recipient
const amountWei = '0x16345785d8a0000'; // 0.1 ETH in wei

window.ethereum.request({
  method: 'eth_sendTransaction',
  params: [{
    from: userAddress,
    to: '0xRecipientAddress...',
    value: amountWei,
    gas: '0x5208' // 21000 gas
  }]
})
.then(txHash => {
  console.log('交易已发送: ', txHash);
  // 可以在 block explorer 查看
  const url = 'https://etherscan.io/tx/' + txHash;
  window.open(url, '_blank');
})
.catch(error => {
  console.error('用户拒绝交易', error);
});

返回结果：

string - 交易哈希 0x...
eth_signTransaction 需要授权
功能：签名交易但不广播，返回签名后的原始交易数据。DApp 需要自己广播。
调用示例： 
window.ethereum.request({
  method: 'eth_signTransaction',
  params: [{
    from: userAddress,
    to: contractAddress,
    value: '0x0',
    gas: '0x...',
    data: encodedFunctionData
  }]
})
.then(signedTx => {
  console.log('已签名: ', signedTx);
  // 需要自己广播 signedTx 到节点
  return fetch(rpcUrl, {
    method: 'POST',
    body: JSON.stringify({
      jsonrpc: '2.0',
      method: 'eth_sendRawTransaction',
      params: [signedTx]
    })
  });
});

六、查询相关

eth_getBalance 无需授权
功能：查询地址的 ETH 余额，返回 wei 单位的十六进制。
调用示例： 
const address = '0x...';

window.ethereum.request({
  method: 'eth_getBalance',
  params: [address, 'latest']  // 'latest' 获取最新余额
})
.then(balanceHex => {
  // 转换为 ETH
  const wei = BigInt(balanceHex);
  const eth = Number(wei) / 1e18;
  console.log(`Balance: ${eth} ETH`);
});
eth_blockNumber 无需授权
功能：获取当前最新块号。
调用示例： 
window.ethereum.request({
  method: 'eth_blockNumber'
})
.then(blockHex => {
  const blockNumber = parseInt(blockHex, 16);
  console.log('当前块高: ', blockNumber);
});
eth_call 无需授权
功能：调用智能合约只读方法（不需要发送交易，不改变状态）。
调用示例（读取 ERC20 余额）： 
// 读取 ERC20 余额
// 方法: balanceOf(address) → 编码后 data 是:
// 0x70a08231 + 地址填充到32字节
const contractAddress = '0xa0b86991c6218b36c1d19d4a2e9eb0ce3606eb48'; // USDC
const userAddress = '0x...';

// 编码: balanceOf(userAddress)
const data = '0x70a08231' +
  userAddress.slice(2).padStart(64, '0');

window.ethereum.request({
  method: 'eth_call',
  params: [{
    to: contractAddress,
    data: data
  }, 'latest']
})
.then(result => {
  // result 是十六进制，转换为数字
  const balanceWei = BigInt(result);
  // USDC 是 6 位小数
  const balance = Number(balanceWei) / 1e6;
  console.log(`USDC 余额: ${balance}`);
});

六、事件监听

除了请求方法，DApp 需要监听钱包推送的事件，比如用户切换账户、切换网络。

chainChanged
功能：当用户切换网络时触发，参数是新的链 ID（十六进制字符串）。
监听示例： 
window.ethereum.on('chainChanged', (chainId) => {
  console.log('网络切换到: ', chainId);
  // 大多数 DApp 选择刷新页面
  window.location.reload();
});
accountsChanged
功能：当用户切换账户时触发，参数是新的账户地址数组。
监听示例： 
window.ethereum.on('accountsChanged', (accounts) => {
  if (accounts.length === 0) {
    console.log('用户断开连接');
    // 清空当前状态
    currentAddress = null;
  } else {
    const newAddress = accounts[0];
    if (newAddress !== currentAddress) {
      console.log('切换到账户: ', newAddress);
      currentAddress = newAddress;
      // 更新页面
      updateUI();
    }
  }
});

完整连接示例

下面是一个完整的 DApp 连接钱包的示例代码，从连接到监听事件：

// 检查是否有 MetaMask / 兼容钱包
if (!window.ethereum) {
  alert('请安装 MetaMask 或其他以太坊钱包');
}

let currentAddress = null;
let currentChainId = null;

// 连接钱包
async function connectWallet() {
  try {
    // 1. 请求授权
    const accounts = await window.ethereum.request({
      method: 'eth_requestAccounts'
    });

    currentAddress = accounts[0];
    console.log('已连接: ', currentAddress);

    // 2. 获取当前链 ID
    const chainIdHex = await window.ethereum.request({
      method: 'eth_chainId'
    });
    currentChainId = parseInt(chainIdHex, 16);

    // 3. 获取余额
    const balanceHex = await window.ethereum.request({
      method: 'eth_getBalance',
      params: [currentAddress, 'latest']
    });
    const balance = Number(BigInt(balanceHex)) / 1e18;

    console.log({
      address: currentAddress,
      chainId: currentChainId,
      balance: balance
    });

    // 4. 更新 UI
    updateUI();

    return { address: currentAddress, chainId: currentChainId };

  } catch (error) {
    console.error('连接失败: ', error);
    throw error;
  }
}

// 监听事件
window.ethereum.on('chainChanged', (chainId) => {
  window.location.reload();
});

window.ethereum.on('accountsChanged', (accounts) => {
  if (accounts.length === 0) {
    currentAddress = null;
  } else {
    currentAddress = accounts[0];
  }
  updateUI();
});

// 检查是否已经连接
async function checkConnection() {
  const accounts = await window.ethereum.request({
    method: 'eth_accounts'
  });
  if (accounts.length > 0) {
    currentAddress = accounts[0];
    const chainIdHex = await window.ethereum.request({method: 'eth_chainId'});
    currentChainId = parseInt(chainIdHex, 16);
    updateUI();
  }
}

// 页面加载时检查
document.addEventListener('DOMContentLoaded', () => {
  checkConnection();
});
💡 使用提示：
  • 所有示例遵循 EIP-1193 标准，兼容 MetaMask、Trust Wallet、Coinbase Wallet 等所有主流钱包
  • window.ethereum.request() 返回 Promise，使用 async/await 更简洁
  • 一定要处理错误，用户拒绝授权是正常情况，不是程序错误
  • 必须监听 chainChanged 和 accountsChanged 事件，否则用户切换后 DApp 状态不对

七、合约交互相关

与智能合约交互本质只有两种方式，都是通过 data 字段携带 ABI 编码后的调用数据：

方式 方法 是否消耗 gas 说明
读合约（只读） eth_call ❌ 否 本地模拟执行，不改变链上状态，立即返回结果
写合约（交易） eth_sendTransaction + data ✅ 是 需要用户签名确认，打包上链后改变合约状态
📐 data 字段的编码格式：
data = 函数选择器(4字节) + 参数按 ABI 规则编码
函数选择器 = keccak256("函数签名") 的前 4 个字节。例如 transfer(address,uint256) 的选择器是 0xa9059cbb。 手动编码只适合参数简单的场景，复杂参数建议直接使用 ethers.js 的 Interface 或 web3.js 的 encodeFunctionCall（见本节最后的简化写法）。
常用 ERC20 函数选择器（可直接复制）：
函数签名 选择器 类型 说明
name()0x06fdde03读代币名称
symbol()0x95d89b41读代币符号
decimals()0x313ce567读小数位数
totalSupply()0x18160ddd读总供应量
balanceOf(address)0x70a08231读查询余额
transfer(address,uint256)0xa9059cbb写转账
transferFrom(address,address,uint256)0x23b872dd写代理转账
approve(address,uint256)0x095ea7b3写授权额度
allowance(address,address)0xdd62ed3e读查询授权额度
eth_call 读取合约数据（只读方法） 无需授权
功能：调用合约的只读（view / pure）方法，不发送交易、不消耗 gas、立即返回。每次读取代币信息、查询余额都靠它。
参数：
  • params[0].to - 合约地址。只读调用也是发给合约，所以填合约地址
  • params[0].data - 编码后的调用数据：函数选择器(4字节) + 参数ABI编码。无参数函数（如 name()）只有选择器
  • params[0].from - 可选。调用者地址，合约里 msg.sender 的值，一般省略
  • params[1] - 区块状态，固定传 'latest'（最新区块执行），也可传指定区块号（十六进制）
返回值解码规则：
  • uint256 - 直接 BigInt(result)，就是数值本身
  • address - 取返回值最后 40 个字符，即 '0x' + result.slice(26)
  • bool - BigInt(result) === 1n
  • string / bytes / 动态数组 - 前 32 字节是偏移量，接着 32 字节是长度，之后才是内容（见下面 decodeString）
调用示例（读取 ERC20 的 name / symbol / decimals）： 
// USDC 合约地址（以太坊主网）
const tokenAddress = '0xa0b86991c6218b36c1d19d4a2e9eb0ce3606eb48';

/**
 * 封装一个通用的只读调用函数
 * @param {string} to   - 合约地址
 * @param {string} data - 函数选择器 + ABI 编码参数（0x 开头）
 * @returns {Promise<string>} ABI 编码的返回值，需要自己按类型解码
 */
async function callContract(to, data) {
  return await window.ethereum.request({
    method: 'eth_call',
    params: [
      { to, data },      // 第 1 个参数：交易对象（只读调用，不用 from/value）
      'latest'           // 第 2 个参数：在最新区块状态上模拟执行
    ]
  });
}

// name() 无参数，data 只有 4 字节选择器 0x06fdde03
const nameHex = await callContract(tokenAddress, '0x06fdde03');

// symbol() 同样无参数
const symbolHex = await callContract(tokenAddress, '0x95d89b41');

// decimals() 同样无参数
const decimalsHex = await callContract(tokenAddress, '0x313ce567');

const decimals = parseInt(decimalsHex, 16); // uint8 直接转数字即可

/**
 * 解码 string 类型的返回值
 * 返回结构（按 32 字节一段）：
 *   第 1 段(0~32)：    偏移量 = 0x20，表示字符串数据从第 2 段之后开始
 *   第 2 段(32~64)：   字符串字节长度
 *   第 3 段(64~)：     字符串的 UTF-8 内容（右填充到 32 字节整数倍）
 */
function decodeString(hex) {
  // 去掉 '0x'，按 2 个字符一组转成字节数组
  const bytes = Uint8Array.from(
    hex.slice(2).match(/.{2}/g).map(b => parseInt(b, 16))
  );
  const dataView = new DataView(bytes.buffer);
  const offset = Number(dataView.getBigUint64(0));    // 第 1 段：偏移量（32）
  const length = Number(dataView.getBigUint64(offset)); // 偏移处：字符串长度
  // 长度字段后面就是字符串内容
  return new TextDecoder().decode(bytes.slice(offset + 32, offset + 32 + length));
}

console.log('名称:', decodeString(nameHex));      // "USD Coin"
console.log('符号:', decodeString(symbolHex));    // "USDC"
console.log('小数位:', decimals);                    // 6

返回结果：

string - ABI 编码的返回值（0x...），需要按返回类型解码。调用失败（revert）时抛异常
eth_estimateGas 预估合约调用的 gas 无需授权
功能：在本地模拟执行一次合约调用，预估需要消耗的 gas。发送写合约交易前先预估，可以提前发现会 revert 的调用。
参数：
  • params[0].from - 调用者地址（用户地址）。合约里 msg.sender 的值，必须传，否则余额/授权检查会不准
  • params[0].to - 合约地址
  • params[0].data - 编码后的调用数据，和实际发送交易时的 data 完全一致
  • params[0].value - 可选。随交易发送的主链币数量（十六进制 wei），payable 方法才需要
调用示例（预估 ERC20 transfer 的 gas）： 
const tokenAddress = '0xa0b8...eb48'; // 代币合约地址
const toAddress = '0xRecipientAddress...'; // 收款人地址
const amount = '10000000'; // 转账数量（最小单位）：10 USDC（6 位小数）

/**
 * 编码 transfer(address,uint256) 的调用数据
 * 结构：'0xa9059cbb'（transfer 的选择器）
 *     + 收款人地址左填充到 32 字节（64 个 hex 字符）
 *     + 金额左填充到 32 字节
 */
const data = '0xa9059cbb'
  + toAddress.slice(2).toLowerCase().padStart(64, '0') // 地址：去 0x，补零到 64 位
  + BigInt(amount).toString(16).padStart(64, '0');        // 金额：转十六进制，补零到 64 位

try {
  const gasHex = await window.ethereum.request({
    method: 'eth_estimateGas',
    params: [{
      from: userAddress,   // 用户地址：合约会用它检查余额和授权额度
      to: tokenAddress,    // 合约地址
      data: data           // 和真实交易完全相同的调用数据
    }]
  });
  // 返回的是十六进制字符串，如 '0xb2a0'
  const gasLimit = parseInt(gasHex, 16);
  console.log('预估 gas:', gasLimit);
  // 实际发送时一般加 10%~20% 余量，避免链上实际消耗略高于预估
  // 实际手续费 ≈ gasUsed × gasPrice（EIP-1559 下 ≈ gasUsed × baseFee + 小费）
} catch (error) {
  // 走到这里说明本地模拟执行就失败了（余额不足 / 未授权 / 参数非法），
  // 这笔交易发上去也必定失败白扣 gas，应该提示用户而不是继续发送
  console.error('调用会失败（revert），不要发送这笔交易', error);
}

返回结果：

string - gas 数量（十六进制）。如果调用必定失败，直接返回错误，这是很好的前置检查手段
eth_sendTransaction 调用合约写入方法 需要授权
功能：向合约地址发送携带 data 的交易，调用合约的写入方法。to 填合约地址，value 一般为 0x0（除非方法是 payable）。
参数（params[0] 交易对象）：
  • from - 用户地址（必须是自己），交易的付款方
  • to - 合约地址（不是收款人！收款人写在 data 里）
  • value - 随交易发送的主链币数量（十六进制 wei）。普通代币操作填 '0x0'，只有 payable 方法需要传值
  • data - 编码后的合约调用数据：函数选择器(4字节) + 按声明顺序编码的参数
  • gas - 可选。gas 上限（十六进制），不传由钱包自动估算
  • gasPrice / maxFeePerGas + maxPriorityFeePerGas - 可选。手续费价格（十六进制），不传由钱包按当前网络情况给出建议值
调用示例（ERC20 代币转账）： 
const tokenAddress = '0xa0b86991c6218b36c1d19d4a2e9eb0ce3606eb48'; // USDC 合约地址
const toAddress = '0xRecipientAddress...'; // 收款人地址（填进 data，不是 to！）
const amount = '10000000'; // 转账数量（最小单位）：10 USDC = 10 × 10^6（USDC 是 6 位小数）

/**
 * ABI 编码辅助函数
 * ABI 规定：每个参数占 32 字节（64 个 hex 字符），不足左补零
 */
// 地址编码：去掉 '0x' 前缀，转小写，左补零到 64 个字符
function encodeAddress(addr) {
  return addr.slice(2).toLowerCase().padStart(64, '0');
}
// 整数编码：转成十六进制字符串，左补零到 64 个字符（用 BigInt 防止超出 Number 精度）
function encodeUint(n) {
  return BigInt(n).toString(16).padStart(64, '0');
}

// 拼出完整 data：transfer 选择器 + 第 1 个参数(收款人) + 第 2 个参数(金额)
// 参数顺序必须和函数声明一致：transfer(address to, uint256 amount)
const data = '0xa9059cbb' + encodeAddress(toAddress) + encodeUint(amount);

// 发送交易，钱包会弹出确认框展示这笔调用，用户批准后签名并广播
window.ethereum.request({
  method: 'eth_sendTransaction',
  params: [{
    from: userAddress,      // 用户自己的地址（付款方）
    to: tokenAddress,       // ⚠️ 是代币合约地址，不是收款人地址！
    value: '0x0',           // 代币转账不随交易发 ETH，金额在 data 里
    data: data              // 合约调用数据（上面编码好的）
  }]
})
.then(txHash => {
  // 交易已广播到网络，但此时还不能确定成功
  console.log('交易已广播:', txHash);
  // 交易上链 ≠ 合约执行成功（可能 revert），还需要查回执确认，见下一节
})
.catch(error => {
  // 常见错误码 4001 = 用户拒绝了签名请求
  console.error('用户拒绝或交易失败', error);
});
⚠️ 常见错误：写合约时 to 必须填合约地址。很多新手把 to 填成收款人地址，结果变成一笔主链币转账而不是代币转账。代币的接收人写在 data 参数里。
ERC20 approve 授权（DApp 最常见的合约写入） 需要授权
功能：授权第三方合约（如 DEX、借贷协议）动用你的代币。几乎所有 DeFi 操作的第一步都是先 approve 再调用业务合约。
参数说明：
  • to - 代币合约地址（授权的是「这个代币」，不是业务合约）
  • spender（data 第 1 个参数）- 被授权的业务合约地址，之后它可以代表你转走该代币
  • amount（data 第 2 个参数）- 授权数量（最小单位）。传 uint256 最大值表示无限授权；传 0 可以撤销已有授权
调用示例（授权 Uniswap 路由合约使用 USDC）： 
const tokenAddress = '0xa0b86991c6218b36c1d19d4a2e9eb0ce3606eb48'; // USDC 合约地址
const spender = '0xE592427A0AEce92De3Edee1F18E0157C05861564'; // Uniswap V3 路由（被授权方）
// uint256 最大值 = 2^256 - 1，即“无限授权”；更安全的做法是只授权本次需要的数量
const amount = '115792089237316195423570985008687907853269984665640564039457584007913129639935';

// 编码 approve(address,uint256)：
// '0x095ea7b3' 是 approve 的选择器，第 1 个参数 spender，第 2 个参数 amount
const data = '0x095ea7b3'
  + spender.slice(2).toLowerCase().padStart(64, '0') // 被授权的合约地址
  + BigInt(amount).toString(16).padStart(64, '0');        // 授权数量

// 发送授权交易，用户在钱包里确认
const txHash = await window.ethereum.request({
  method: 'eth_sendTransaction',
  params: [{
    from: userAddress,   // 授权人（自己）
    to: tokenAddress,    // 代币合约地址
    data: data           // approve 调用数据
  }]
});
console.log('授权交易:', txHash);

/**
 * 可选：授权前用 allowance(address,address) 查询现有额度，够用就不用重复授权
 * 参数顺序：第 1 个是 owner（自己），第 2 个是 spender（被授权方）
 */
const allowanceData = '0xdd62ed3e'
  + userAddress.slice(2).toLowerCase().padStart(64, '0') // owner
  + spender.slice(2).toLowerCase().padStart(64, '0');        // spender
const allowanceHex = await window.ethereum.request({
  method: 'eth_call',
  params: [{ to: tokenAddress, data: allowanceData }, 'latest']
});
// 返回 uint256，直接 BigInt 转换；大于本次所需数量就不用再 approve
console.log('当前授权额度:', BigInt(allowanceHex).toString());
⚠️ 安全提示：无限授权（uint256 最大值）虽然省 gas，但恶意合约一旦拿到授权可以转走你的全部代币。正规 DApp 一般默认只授权所需数量，钱包也会对无限授权弹出高风险提示。
eth_getTransactionReceipt 确认合约执行结果 无需授权
功能：查询交易回执。拿到交易哈希 ≠ 执行成功——合约执行可能 revert（此时 gas 照扣）。必须等回执出现并检查 status 字段。
参数与返回值：
  • params[0] - 要查询的交易哈希（eth_sendTransaction 的返回值）
  • 返回 receipt.status - '0x1' 执行成功；'0x0' 执行失败（revert，gas 照扣）
  • 返回 receipt.blockNumber - 打包进的区块号（十六进制）
  • 返回 receipt.gasUsed - 实际消耗的 gas（十六进制），用于计算真实手续费
  • 返回 receipt.logs - 合约触发的事件数组（如 Transfer / Approval）
调用示例（轮询等待合约执行结果）： 
/**
 * 轮询等待交易上链并返回回执
 * @param {string} txHash  - eth_sendTransaction 返回的交易哈希
 * @param {number} interval - 轮询间隔（毫秒），以太坊出块约 12 秒，默认 3 秒查一次足够
 * @returns {Promise<object>} 回执对象（上链后才会返回，否则一直轮询）
 */
async function waitReceipt(txHash, interval = 3000) {
  while (true) {
    // 查询回执：还没上链时返回 null，上链后返回回执对象
    const receipt = await window.ethereum.request({
      method: 'eth_getTransactionReceipt',
      params: [txHash]  // 唯一参数：交易哈希
    });

    if (receipt) {
      // 交易已上链，检查 status 判断合约是否执行成功
      // status: '0x1' 成功，'0x0' 失败（revert，gas 照扣不退）
      const success = receipt.status === '0x1';
      console.log(success ? '✅ 合约执行成功' : '❌ 合约执行失败');
      console.log('执行区块:', parseInt(receipt.blockNumber, 16));
      console.log('实际消耗 gas:', parseInt(receipt.gasUsed, 16));
      // 合约方法触发的 Transfer / Approval 等事件都在 receipt.logs 里
      return receipt;
    }

    // receipt 为 null：还没被打包，等几秒再查
    await new Promise(r => setTimeout(r, interval));
  }
}

// 用法：发送交易后等待确认
const txHash = await window.ethereum.request({
  method: 'eth_sendTransaction',
  params: [{ from: userAddress, to: tokenAddress, data: data }]
});
const receipt = await waitReceipt(txHash);
// 只有 status === '0x1' 才算真正成功，才能继续后面的业务逻辑
if (receipt.status !== '0x1') {
  alert('合约执行失败，请检查余额、授权额度或参数');
}

返回结果：

未上链返回 null；上链后返回回执对象，关键字段：status（0x1 成功 / 0x0 失败）、blockNumber、gasUsed、logs（合约事件）
eth_getLogs 查询合约事件 无需授权
功能：按合约地址、事件主题、区块范围筛选链上事件日志，可用于解析历史转账记录等。
参数（params[0] 过滤条件）：
  • address - 要筛选的合约地址（事件必须由这个合约发出）
  • topics - 事件主题数组：topics[0] 是事件签名的 keccak256 哈希（如 Transfer），topics[1] 起依次对应 indexed 参数。传 null 表示该位置不限
  • fromBlock - 起始区块号（十六进制），如 '0x1283F00'
  • toBlock - 结束区块号，传 'latest' 表示到最新块
📌 Transfer 事件的 topics 结构：
Transfer(address indexed from, address indexed to, uint256 value)
topics[0] = 事件签名哈希；topics[1] = from 地址（indexed 参数，左填充 32 字节）；topics[2] = to 地址；非 indexed 的 value 不在 topics 里，放在 data 中。
调用示例（查询某 USDC 的 Transfer 事件）： 
const tokenAddress = '0xa0b86991c6218b36c1d19d4a2e9eb0ce3606eb48'; // USDC 合约
// Transfer(address,address,uint256) 的事件签名 keccak256 哈希（完整 32 字节，作为 topic0）
const transferTopic = '0xddf252ad1be2c89b69c2b068fc378daa952ba7f163c4a11628f55a4df523b3ef';

// 按接收方地址过滤：topics[2] 对应 to 参数，地址左填充到 32 字节（'0x' + 24 个零 + 40 位地址）
const toTopic = '0x000000000000000000000000'
  + userAddress.slice(2).toLowerCase();

const logs = await window.ethereum.request({
  method: 'eth_getLogs',
  params: [{
    address: tokenAddress,                      // 只查这个合约发出的事件
    topics: [transferTopic, null, toTopic],    // topic0=Transfer，topic1(from)不限，topic2(to)=用户地址
    fromBlock: '0x1283F00',                    // 起始区块（十六进制）
    toBlock: 'latest'                          // 到最新区块
  }]
});

// 遍历匹配到的事件日志，解析出转账信息
logs.forEach(log => {
  // indexed 地址参数存放在 topics 里，每个占 32 字节，取最后 40 个字符还原地址
  const from = '0x' + log.topics[1].slice(26);
  const to = '0x' + log.topics[2].slice(26);
  // 非 indexed 的 value 存放在 data 里，直接 BigInt 转换
  const value = BigInt(log.data);
  console.log(`${from} → ${to}: ${value} (区块 ${parseInt(log.blockNumber, 16)})`);
});
💡 注意：大多数节点对单次查询的区块范围有限制（如 1000~10000 块），范围过大或结果过多会报错，需要分批查询。

用 ethers.js 简化合约交互（推荐）

上面的手动 ABI 编码只适合参数简单的场景。实际项目推荐用 ethers.js，它会自动完成编码和解码：

// npm install ethers （浏览器直接引入也行）
import { BrowserProvider, Contract } from 'ethers';

// BrowserProvider 包装 window.ethereum，内部所有读写都会走 eth_call / eth_sendTransaction
const provider = new BrowserProvider(window.ethereum);
// signer = 已连接的用户账户；读合约可以只用 provider，写合约必须用 signer
const signer = await provider.getSigner();

/**
 * 最小 ABI：只声明用到的函数即可，不用完整 ERC20 ABI
 * 格式：'function 函数名(参数) [view] returns (返回类型)'
 * 读写由 ethers 自动区分：带 view 的走 eth_call，其余走 eth_sendTransaction
 */
const erc20Abi = [
  'function name() view returns (string)',
  'function decimals() view returns (uint8)',
  'function balanceOf(address) view returns (uint256)',
  'function transfer(address to, uint256 amount) returns (bool)',
  'function approve(address spender, uint256 amount) returns (bool)'
];

// 创建合约实例：地址 + ABI + signer（写）或 provider（只读）
const usdc = new Contract('0xa0b86991c6218b36c1d19d4a2e9eb0ce3606eb48', erc20Abi, signer);

// 读合约：自动调用 eth_call 并解码返回值，直接得到 JS 类型的结果
const name = await usdc.name();              // "USD Coin"（string）
const decimals = await usdc.decimals();       // 6（number）
const balance = await usdc.balanceOf(userAddress); // BigInt，最小单位
console.log(name, Number(balance) / 10 ** decimals);

// 写合约：自动编码 data 并调用 eth_sendTransaction，钱包弹窗签名，返回 TransactionResponse
const tx = await usdc.transfer(toAddress, '10000000'); // 10 USDC
console.log('txHash:', tx.hash);

// 等待上链并拿到回执（内部自动轮询 eth_getTransactionReceipt）
// receipt.status === 1 表示合约执行成功
const receipt = await tx.wait();
console.log(receipt.status === 1 ? '成功' : '失败');
