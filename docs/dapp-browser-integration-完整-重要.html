第一部分：DApp 调用钱包 - 常用方法及示例

本文档列出了 DApp 与以太坊钱包交互最常用的 JSON-RPC 方法，包含完整的调用示例，可直接复制使用。

📋 统一调用格式：
所有方法都遵循 EIP-1193 标准 window.ethereum.request(args) 格式： 
window.ethereum.request({
  method: 'method_name',
  params: [...]
})
.then(result => {
  // 处理成功结果
})
.catch(error => {
  // 用户拒绝或出错
});

一、授权相关

eth_requestAccounts 需要授权
功能：请求用户授权连接钱包，获取用户账户地址列表。这是 DApp 与钱包交互的第一步。
调用示例： 
window.ethereum.request({
  method: 'eth_requestAccounts',
  params: []
})
.then(accounts => {
  // accounts = ["0x1234...abcd"]
  console.log('用户地址:', accounts[0]);
  // 保存用户地址
  userAddress = accounts[0];
})
.catch(error => {
  console.error('用户拒绝连接', error);
});

返回结果：

string[] - 授权的账户地址数组，第一个是当前选中地址
eth_requestPermissions 需要授权
功能：请求特定权限（EIP-2255），主要用于请求账户访问权限。
调用示例： 
window.ethereum.request({
  method: 'eth_requestPermissions',
  params: [{
    eth_accounts: {}
  }]
})
.then(permissions => {
  console.log('权限已批准', permissions);
  // 权限批准后再获取账户
  return window.ethereum.request({
    method: 'eth_accounts'
  });
})
.catch(error => {
  console.error('权限被拒绝', error);
});

二、账户相关

eth_accounts 无需授权
功能：获取当前已授权的账户地址列表。如果还没授权返回空数组。
调用示例： 
window.ethereum.request({
  method: 'eth_accounts'
})
.then(accounts => {
  if (accounts.length > 0) {
    console.log('已连接: ', accounts[0]);
    currentAddress = accounts[0];
  } else {
    console.log('未连接');
  }
});

返回结果：

string[] - 已授权账户地址数组，如果未授权返回空数组
eth_coinbase 无需授权
功能：获取当前选中的 coinbase 地址（就是当前用户账户地址）。
调用示例： 
window.ethereum.request({
  method: 'eth_coinbase'
})
.then(address => {
  console.log('当前地址: ', address);
});

返回结果：

string | null - 当前地址，未连接返回 null

三、网络相关

eth_chainId 无需授权
功能：获取当前连接区块链的链 ID，返回十六进制字符串。
调用示例： 
window.ethereum.request({
  method: 'eth_chainId'
})
.then(chainIdHex => {
  const chainId = parseInt(chainIdHex, 16);
  console.log('当前链 ID: ', chainId);

  // 检查是否是正确网络
  if (chainId !== 1) {
    console.warn('请切换到以太坊主网');
  }
});

常见链 ID：

  • 以太坊主网: 0x1 → 1
  • BSC: 0x38 → 56
  • Polygon: 0x89 → 137
  • Avalanche: 0xa86a → 43114
net_version 无需授权
功能：获取网络版本（其实就是链 ID，返回十进制字符串）。这是旧方法，推荐使用 eth_chainId。
调用示例： 
window.ethereum.request({
  method: 'net_version'
})
.then(chainIdStr => {
  const chainId = parseInt(chainIdStr, 10);
  console.log('链 ID: ', chainId);
});

四、签名相关

personal_sign 需要授权
功能：对个人消息进行签名，这是最常用的签名方法。标准参数顺序是 [message, address]。
参数：
  • params[0] - 要签名的消息（十六进制）
  • params[1] - 签名账户地址
调用示例： 
// 将要签名的消息转成十六进制
const message = 'Hello DApp! Please sign to confirm your identity.';
const messageHex = Buffer.from(message).toString('hex');
const signerAddress = '0x1234...';

window.ethereum.request({
  method: 'personal_sign',
  params: ['0x' + messageHex, signerAddress]
})
.then(signature => {
  console.log('签名结果: ', signature);
  // 将签名发送到后端验证
  return fetch('/api/verify', {
    method: 'POST',
    body: JSON.stringify({
      message, signature, address: signerAddress
    })
  });
})
.catch(error => {
  console.error('用户拒绝签名', error);
});

返回结果：

string - 65字节的签名，格式 0x...

五、交易相关

eth_sendTransaction 需要授权
功能：发送交易，由钱包完成签名并广播到网络。DApp 只需要构造交易，用户批准后钱包处理剩下的。
调用示例（ETH 转账）： 
// 转账 0.1 ETH 到 recipient
const amountWei = '0x16345785d8a0000'; // 0.1 ETH in wei

window.ethereum.request({
  method: 'eth_sendTransaction',
  params: [{
    from: userAddress,
    to: '0xRecipientAddress...',
    value: amountWei,
    gas: '0x5208' // 21000 gas
  }]
})
.then(txHash => {
  console.log('交易已发送: ', txHash);
  // 可以在 block explorer 查看
  const url = 'https://etherscan.io/tx/' + txHash;
  window.open(url, '_blank');
})
.catch(error => {
  console.error('用户拒绝交易', error);
});

返回结果：

string - 交易哈希 0x...

六、查询相关

eth_getBalance 无需授权
功能：查询地址的 ETH 余额，返回 wei 单位的十六进制。
调用示例： 
const address = '0x...';

window.ethereum.request({
  method: 'eth_getBalance',
  params: [address, 'latest']  // 'latest' 获取最新余额
})
.then(balanceHex => {
  // 转换为 ETH
  const wei = BigInt(balanceHex);
  const eth = Number(wei) / 1e18;
  console.log(`Balance: ${eth} ETH`);
});

七、事件监听

除了请求方法，DApp 需要监听钱包推送的事件，比如用户切换账户、切换网络。

chainChanged
功能：当用户切换网络时触发，参数是新的链 ID（十六进制字符串）。
监听示例： 
window.ethereum.on('chainChanged', (chainId) => {
  console.log('网络切换到: ', chainId);
  // 大多数 DApp 选择刷新页面
  window.location.reload();
});
accountsChanged
功能：当用户切换账户时触发，参数是新的账户地址数组。
监听示例： 
window.ethereum.on('accountsChanged', (accounts) => {
  if (accounts.length === 0) {
    console.log('用户断开连接');
    // 清空当前状态
    currentAddress = null;
  } else {
    const newAddress = accounts[0];
    if (newAddress !== currentAddress) {
      console.log('切换到账户: ', newAddress);
      currentAddress = newAddress;
      // 更新页面
      updateUI();
    }
  }
});

完整连接示例

下面是一个完整的 DApp 连接钱包的示例代码，从连接到监听事件：

// 检查是否有 MetaMask / 兼容钱包
if (!window.ethereum) {
  alert('请安装 MetaMask 或其他以太坊钱包');
}

let currentAddress = null;
let currentChainId = null;

// 连接钱包
async function connectWallet() {
  try {
    // 1. 请求授权
    const accounts = await window.ethereum.request({
      method: 'eth_requestAccounts'
    });

    currentAddress = accounts[0];
    console.log('已连接: ', currentAddress);

    // 2. 获取当前链 ID
    const chainIdHex = await window.ethereum.request({
      method: 'eth_chainId'
    });
    currentChainId = parseInt(chainIdHex, 16);

    // 3. 获取余额
    const balanceHex = await window.ethereum.request({
      method: 'eth_getBalance',
      params: [currentAddress, 'latest']
    });
    const balance = Number(BigInt(balanceHex)) / 1e18;

    console.log({
      address: currentAddress,
      chainId: currentChainId,
      balance: balance
    });

    // 4. 更新 UI
    updateUI();

    return { address: currentAddress, chainId: currentChainId };

  } catch (error) {
    console.error('连接失败: ', error);
    throw error;
  }
}

// 监听事件
window.ethereum.on('chainChanged', (chainId) => {
  window.location.reload();
});

window.ethereum.on('accountsChanged', (accounts) => {
  if (accounts.length === 0) {
    currentAddress = null;
  } else {
    currentAddress = accounts[0];
  }
  updateUI();
});

// 检查是否已经连接
async function checkConnection() {
  const accounts = await window.ethereum.request({
    method: 'eth_accounts'
  });
  if (accounts.length > 0) {
    currentAddress = accounts[0];
    const chainIdHex = await window.ethereum.request({method: 'eth_chainId'});
    currentChainId = parseInt(chainIdHex, 16);
    updateUI();
  }
}

// 页面加载时检查
document.addEventListener('DOMContentLoaded', () => {
  checkConnection();
});
💡 使用提示：
  • 所有示例遵循 EIP-1193 标准，兼容 MetaMask、Trust Wallet、Coinbase Wallet 等所有主流钱包
  • window.ethereum.request() 返回 Promise，使用 async/await 更简洁
  • 一定要处理错误，用户拒绝授权是正常情况，不是程序错误
  • 必须监听 chainChanged 和 accountsChanged 事件，否则用户切换后 DApp 状态不对

示例二：ETH 转账（ethers v6）

import { BrowserProvider, Transaction } from 'ethers';

// ETH 转账 - 原生 ethers 方式
async function transferETH(
  to: string,
  amount: string // 单位 ETH
) {
  // 1. 创建 provider
  const provider = new BrowserProvider(window.ethereum);
  const signer = await provider.getSigner();
  const from = await signer.getAddress();

  // 2. 估算 gas
  const feeData = await provider.getFeeData();
  const gasLimit = await provider.estimateGas({
    to,
    value: parseEther(amount),
  });

  // 3. 创建交易
  const tx = await signer.populateTransaction({
    to,
    value: parseEther(amount),
    gasLimit: gasLimit * 1n + 21000n,
    maxFeePerGas: feeData.maxFeePerGas,
    maxPriorityFeePerGas: feeData.maxPriorityFeePerGas,
    nonce: await provider.getTransactionCount(from),
  });

  // 4. 发送交易（钱包签名并广播）
  const txResponse = await signer.sendTransaction(tx);
  console.log('交易哈希: ', txResponse.hash);

  // 5. 等待交易确认
  const receipt = await txResponse.wait();
  if (receipt.status === 1) {
    console.log('转账成功！');
  }
}

示例四：调用合约只读方法（ethers v6）

import { BrowserProvider, Contract } from 'ethers';

// 读取 ERC20 余额
async function getERC20Balance(
  contractAddress: string,
  ownerAddress: string,
  decimals: number
) {
  // ERC20 ABI 只需要我们用到的方法
  const abi = [
    'function balanceOf(address owner) view returns (uint256)',
    'function decimals() view returns (uint8)',
  ];

  // 1. 创建 provider 和 contract 实例
  const provider = new BrowserProvider(window.ethereum);
  const contract = new Contract(contractAddress, abi, provider);

  // 2. 调用只读方法（不需要钱包签名，直接 RPC 查询）
  const balance = await contract.balanceOf(ownerAddress);
  const formatted = Number(balance) / (10 ** decimals);

  return formatted;
}

// 使用
const balance = await getERC20Balance(
  '0xa0b86991c6218b36c1d19d4a2e9eb0ce3606eb48', // USDC
  userAddress,
  6
);
console.log(`USDC 余额: ${balance}`);

示例五：调用合约写方法（ethers v6）

import { BrowserProvider, Contract } from 'ethers';

// DEX 兑换 - 调用 swap 方法
async function swapTokens(
  contractAddress: string,
  amountIn: bigint,
  minAmountOut: bigint,
  to: string
) {
  const abi = [
    'function swap(uint amountIn, uint minAmountOut, address to) returns (uint amountOut)',
  ];

  const provider = new BrowserProvider(window.ethereum);
  const signer = await provider.getSigner();
  const contract = new Contract(contractAddress, abi, signer);

  try {
    // 调用合约方法 - 钱包会弹出确认
    const tx = await contract.swap(amountIn, minAmountOut, to);
    console.log('交易已发送: ', tx.hash);

    // 等待确认
    const receipt = await tx.wait();
    if (receipt.status === 1) {
      console.log('兑换成功！');
      return receipt;
    }
  } catch (error) {
    if (error.code === 'ACTION_REJECTED') {
      console.log('用户拒绝了交易');
    } else {
      throw error;
    }
  }
}
📋 wagmi vs ethers 区别：
  • wagmi - React Hooks 封装，适合 React DApp，很多事情自动处理，代码更简洁
  • ethers - 底层库，不依赖 React，任何框架都能用，更灵活
  • 两者都兼容标准 EIP-1193，trust-min 都能正常工作

常见问题与调试排错

Q1: DApp 调用后没有响应，在哪里看日志？

解决：打开网页 Safari 开发者工具 → Console 标签，你的 glue code 已经打了很多日志：

// 你的代码有这些日志
console.log("[glue] ✅ trust-min.js loaded");
console.log("[trust-min] outgoing postMessage called!", obj);
console.log("[native-patch] ✅ Patched window.ethereum.request");

可以根据日志判断请求走到哪一步了：

  • 日志没有输出 → trust-min.js 没注入成功
  • 没看到 [trust-min] outgoing postMessage → 请求没走到 trust-min
  • 日志输出了 → 看原生 Xcode 控制台，Swift 是否收到

Q2: 用户切换账户后，DApp 没收到更新？

原因：DApp 监听了 accountsChanged，但是你切换账户后没有调用 emit 通知 DApp

解决：切换账户后在 Swift 中执行：

// Swift 代码
let script = """
if (window.ethereum) {
    window.ethereum.emit('accountsChanged', ['\(newAddress)']);
}
"""
webView.evaluateJavaScript(script)

Q3: 用户切换网络后，DApp 没更新？

解决：类似上面，切换网络后需要：

// Swift 代码
let chainIdHex = "0x" + String(chainId, radix: 16)
let script = """
if (window.ethereum) {
    window.ethereum.emit('chainChanged', '\(chainIdHex)');
}
"""
webView.evaluateJavaScript(script)

Q4: 签名返回 DApp 校验不通过？

常见原因：

  1. personal_sign 参数顺序反了 → 标准顺序是 [message, address]
  2. 缺少 Ethereum 前缀 → 需要添加 \x19Ethereum Signed Message:\nlen 前缀
  3. 签名大小写问题 → 返回结果应该是 0x... 小写 hex

Q5: 如何打开 Safari 调试 WKWebView？

步骤：

  1. iPhone 设置 → Safari → 高级 → Web 检查器 → 打开
  2. Mac Safari 开发 → 打开 → 选择 iPhone 上的 WKWebView
  3. 就能看到 Console 和 Network 了

Q6: trust-min 注入顺序错了会怎样？

你的代码已经是正确顺序：

1. trust-min.js 先运行 → 创建 window.trustwallet
2. 你的 glue code 后运行 → 替换 postMessage + 创建 window.ethereum

如果反过来，你的代码先运行，trust-min 会覆盖 window.trustwallet，你的 postMessage 就没了 → 收不到请求

当前代码顺序正确 ✅

Q7: 怎么检查 window.ethereum 创建成功了？

在 Safari 控制台执行：

console.log("window.ethereum exists: ", !!window.ethereum);
console.log("window.trustwallet exists: ", !!window.trustwallet);
console.log("window.ethereum.request: ", typeof window.ethereum.request);
console.log("window.ethereum.sendResponse: ", typeof window.ethereum.sendResponse);

如果都是 function 说明创建成功

Q8: iOS 隐私追踪提示框导致消息丢失？

解决：弹窗结束后刷新页面，或者延迟注入，等弹窗结束再注入

第二部分：钱包处理请求 - 与区块链交互流程

当钱包（原生应用）收到来自 DApp 的请求后，需要根据请求类型进行不同处理，最终与区块链节点交互得到结果，再返回给 DApp。

一、整体处理流程

1️⃣ DApp → 钱包
DApp 通过 window.ethereum.request() 发起请求 → trust-min → window.trustwallet.postMessage → 原生钱包收到请求
↓
2️⃣ 钱包分类处理
根据请求方法判断类型：只读请求 / 授权请求 / 签名请求 / 交易请求
↓
3️⃣ 需要用户授权吗？
否 → 直接处理
是 → 弹出确认弹窗，等待用户操作
↓
4️⃣ 与区块链交互
只读请求 → 转发给 RPC 节点 → 直接返回结果
签名/交易 → 使用本地私钥签名 → 广播到节点
↓
5️⃣ 钱包 → DApp
结果通过 window.ethereum.sendResponse(id, result) 返回给 trust-min → trust-min resolve Promise → DApp 得到结果
核心设计思想：
  • 分层处理：trust-min 负责协议转换，原生钱包负责安全存储私钥和实际交互
  • 安全第一：私钥永远留在原生环境，所有签名都在原生完成
  • 用户掌控：所有涉及签名和交易的操作必须经用户确认

二、请求类型分类

分类 方法举例 需要用户确认 需要私钥操作 与链交互
只读请求 eth_getBalance, eth_call, eth_blockNumber ❌ 不需要 ❌ 不需要 ✅ 需要（转发 RPC）
授权请求 eth_requestAccounts ✅ 需要 ❌ 不需要 ❌ 不需要
签名请求 personal_sign, eth_signTypedData_v4 ✅ 需要 ✅ 需要 ❌ 不需要（只签名不广播）
交易请求 eth_sendTransaction, eth_signTransaction ✅ 需要 ✅ 需要 ✅ 需要（签名后广播）

三、只读请求处理

只读请求 不改变链上状态，不需要用户授权，也不需要私钥，直接转发给区块链节点就可以了。

处理流程：直接转发 RPC

1. 原生收到请求：eth_getBalance，参数：[address, "latest"]
↓
2. 构建标准 JSON-RPC 请求： 
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "eth_getBalance",
  "params": ["0x...", "latest"]
}
↓
3. HTTP POST 发送到区块链节点 RPC 接口
↓
4. 节点返回 JSON-RPC 响应
↓
5. 取出 result 返回给 DApp
💡 为什么可以直接转发？
只读请求不需要访问私钥，也不需要用户确认，节点就能回答，所以不用钱包做额外处理，直接透传。

Swift 实现示例

func forwardToRPC(method: String,
             params: Any,
             id: Int,
             rpcURL: URL)
async throws -> Any {

    // 1. 构建 JSON-RPC 请求
    let request: [String: Any] = [
        "jsonrpc": "2.0",
        "id": id,
        "method": method,
        "params": params
    ]

    // 2. 序列化
    let data = try JSONSerialization.data(
        withJSONObject: request,
        options: []
    )

    // 3. 创建 URLRequest
    var urlRequest = URLRequest(url: rpcURL)
    urlRequest.httpMethod = "POST"
    urlRequest.httpBody = data
    urlRequest.setValue(
        "application/json",
        forHTTPHeaderField: "Content-Type"
    )

    // 4. 发送请求
    let (data, response) = try await URLSession.shared
        .data(for: urlRequest)

    // 5. 解析响应
    guard let json = try JSONSerialization
        .jsonObject(with: data) as? [String: Any] else {
        throw RPCError.invalidResponse
    }

    // 6. 检查错误
    if let error = json["error"] {
        throw RPCError.rpcError(error)
    }

    // 7. 返回结果
    return json["result"]!
}

四、授权请求处理

请求方法：eth_requestAccounts

处理流程：

  1. 钱包收到 eth_requestAccounts 请求
  2. 弹出用户授权弹窗，问用户是否允许 DApp 连接钱包
  3. 用户拒绝 → 返回错误给 DApp
  4. 用户批准 → 返回当前选中账户地址数组给 DApp

Swift 示例：

func handleEthRequestAccounts(id: Int, approved: Bool) {
    guard approved else {
        // 用户拒绝，返回错误
        self.sendErrorResponse(
            id: id,
            message: "User rejected the request"
        )
        return
    }

    // 用户批准，返回地址
    if let address = selectedAccount?.address {
        let result = [formatAddress(address)]
        self.sendSuccessResponse(result: result, id: id)
    } else {
        self.sendSuccessResponse(result: [], id: id)
    }

    // 🔥 重要：账户变化后，需要触发事件通知所有已连接的 DApp
    webView.evaluateJavaScript("""
        if (window.ethereum) {
            window.ethereum.emit('accountsChanged', ['\(formatAddress(address))']);
        }
    """)
}
⚠️ 重要提示：
用户授权连接后，如果切换账户，钱包必须通过 window.ethereum.emit('accountsChanged', [newAddress]) 通知 DApp，否则 DApp 状态会不一致。

五、签名请求处理

签名请求需要用户确认，并使用私钥在原生端完成签名。这是钱包最核心的安全功能。

personal_sign 完整处理流程

1️⃣ 收到请求：参数 [messageHex, address]
↓
2️⃣ 检查地址是否是当前选中账户，不是 → 错误
↓
3️⃣ 将十六进制消息解码为可读字符串（如果是文字）
↓
4️⃣ 弹出签名确认弹窗，给用户看要签名的内容
↓
5️⃣ 用户拒绝 → 返回错误
↓
6️⃣ 用户批准 → 从安全存储取出私钥
↓
7️⃣ 使用 secp256k1 对消息哈希进行签名
↓
8️⃣ 返回 65 字节签名给 DApp（格式 0x...）

Swift 签名示例（使用 TrustWalletCore）

func handlePersonalSign(
    params: Any,
    id: Int,
    selectedAccount: AccountModel,
    approved: Bool
) {
    guard approved else {
        sendErrorResponse(id: id, message: "User rejected signing")
        return
    }

    // 1. 解析参数: personal_sign 参数顺序是 [message, address]
    guard let paramsArray = params as? [Any],
          paramsArray.count >= 2,
          let messageHex = paramsArray[0] as? String,
          let _ = paramsArray[1] as? String else {
        sendErrorResponse(
            id: id,
            message: "Invalid parameters for personal_sign"
        )
        return
    }

    // 2. 将消息从 hex 转为 Data
    let messageData = Data(
        hexString: messageHex.stripHexPrefix()
    )!

    // 3. keccak256 哈希 (Ethereum 签名标准)
    let prefixedMessage = "\x19Ethereum Signed Message:\n"
        + String(messageData.count)
        + String(data: messageData, encoding: .utf8)!

    let prefixedData = prefixedMessage.data(using: .utf8)!
    let hash = Hash.keccak256(data: prefixedData)

    // 4. 获取私钥 (从安全存储)
    // ⚠️ 注意：在真实应用中，私钥应该存在 Keychain，这里简化
    guard let privateKeyData = Data(
        hexString: selectedAccount.privateKey
    ),
          let privateKey = PrivateKey(data: privateKeyData) else {
        sendErrorResponse(id: id, message: "Invalid private key")
        return
    }

    // 5. 签名
    let signature = Secp256k1.sign(
        hash: hash,
        privateKey: privateKey
    )

    // 6. 转为 0x 格式返回
    let signatureHex = "0x" + signature.data.hex

    // 7. 返回给 DApp
    sendSuccessResponse(result: signatureHex, id: id)
}
🔒 安全提醒：
  • 私钥必须存储在安全地方（iOS Keychain），不能存在 UserDefaults 或 plist
  • 签名必须在原生应用内完成，私钥绝对不能传到 JS
  • 签名前必须给用户展示要签名的内容，让用户确认

第三部分：EIP-1193 & trust-min 通信原理

第一部分：EIP-1193 标准协议方法

EIP-1193 是 Ethereum Provider JavaScript API 的官方标准协议，定义了 window.ethereum 必须实现的接口。

1.1 核心方法（必须实现）

方法 签名 返回值 描述
request (args: { method: string; params: any[] }) => Promise<any> Promise<any> ✅ 推荐入口，发送 JSON-RPC 请求。现代 DApp 都使用此方法
on (eventName: string, listener: Function) => this Provider instance 添加事件监听器
off (eventName: string, listener: Function) => this Provider instance 移除事件监听器（removeListener 的别名）
removeListener (eventName: string, listener: Function) => this Provider instance 移除事件监听器

1.2 标准事件

事件 参数类型 触发时机
connect { chainId: string } 成功连接到区块链网络
disconnect { code: number; message: string } 断开网络连接
chainChanged chainId: string (hex 格式) 当前连接的链 ID 改变
accountsChanged accounts: string[] 用户选中的账户列表改变
message { type: string; data: any } 接收到通用消息

第二部分：window.trustwallet 对象接口

trust-min.js 加载后会在 window 上创建 window.trustwallet 对象，暴露 Provider 构造函数供调用方使用。

2.1 所有属性和方法

成员 类型 必须由你提供 描述
Provider constructor ❌ Ethereum EIP-1193 Provider 构造函数，用于创建 window.ethereum
postMessage (name: string, id: number, object: any) => void ✅ 必须 trust-min 通过此方法发送请求到原生应用。这是核心出口
TrustSolanaWeb3Provider constructor ❌ Solana 区块链 Provider
TrustAptosWeb3Provider constructor ❌ Aptos 区块链 Provider
getKey function ❌ Cosmos 密钥获取
signAmino function ❌ Cosmos Amino 签名
signDirect function ❌ Cosmos Direct 签名
⚠️ 关键点： window.trustwallet.postMessage 必须由你实现并替换！trust-min 只定义了调用协议，实际实现需要你提供来连接原生应用。

第三部分：window.ethereum Provider 对象方法

当你调用 window.ethereum = new window.trustwallet.Provider(config) 创建实例后，得到一个完整的 EIP-1193 兼容 Provider。

3.1 构造函数配置

原生处理完请求后，必须调用这些方法把结果返回给 trust-min：

方法 签名 何时调用

步骤 调用方 方法

4.4 设计思想

这是 trust-min 设计的分层分离架构：

层次 职责 由谁提供
Provider 层 实现 EIP-1193 标准接口，协议转换 trust-min.js
桥接层 连接 JS 与原生，转发请求和响应 你的应用（glue code）
原生业务层 保存私钥、签名、用户授权、RPC 转发 你的应用（Swift）

优点：

  • ✅ 关注点分离：trust-min 只处理协议转换，不关心原生怎么实现
  • ✅ 跨平台通用：相同的 trust-min 可以在 iOS/Android/浏览器扩展 使用
  • ✅ 安全可控：私钥永远留在原生应用，不会暴露给 JS
  • ✅ 易于维护：协议固定，两边可以独立升级

第五部分：结果返回 DApp + 事件监听原理

5.1 请求结果返回给 DApp 完整流程

1️⃣ DApp 调用
↓
const promise = window.ethereum.request({...});
promise.then(result => {
    // DApp 在这里处理结果
});
↓
2️⃣ trust-min 内部
创建 Promise，将 resolve/reject 存入 this.callbacks 映射表
key 是 request id，value 是回调函数
↓
3️⃣ 发到原生处理
window.trustwallet.postMessage(...) → Swift 处理...
↓
4️⃣ Swift 处理完，回传给 trust-min
↓
// Swift 执行 JS
webView.evaluateJavaScript("""
    window.ethereum.sendResponse(\(id), \(resultJSON));
""")
↓
5️⃣ trust-min 收到结果
↓
// trust-min 源码
this.callbacks.get(id).resolve(result);
this.callbacks.delete(id);
↓
6️⃣ Promise resolved → DApp 的 .then() 执行 ✅
核心原理总结：
  • DApp 调用 request() 得到 Promise
  • trust-min 把 resolve 回调存储起来
  • 原生处理完后调用 window.ethereum.sendResponse()
  • trust-min 取出回调执行 resolve(result)
  • DApp 的 .then() 得到结果

5.2 DApp 用 .on() 监听事件原理

window.ethereum (Provider) 继承自 EventEmitter，所以自带事件系统：

1️⃣ DApp 注册监听
↓
window.ethereum.on('accountsChanged', (accounts) => {
    console.log('账户变化', accounts);
    // 更新 DApp UI
});
↓
2️⃣ EventEmitter 做了什么
把你的 listener 函数存入对应事件的数组里
比如：this.events['accountsChanged'].push(listener)
↓
3️⃣ 等待...（什么也不做，等待事件触发）
↓
4️⃣ 原生状态改变
用户在钱包 App 切换了账户 → 原生需要通知 DApp
↓
// Swift 代码触发事件
webView.evaluateJavaScript("""
    if (window.ethereum) {
        window.ethereum.emit('accountsChanged', \(newAccountsJson));
    }
""")
↓
5️⃣ trust-min EventEmitter 触发事件
取出 accountsChanged 事件所有 listener
逐个调用 listener，传入新参数
↓
6️⃣ DApp 的 listener 执行 ✅
DApp 收到新账户，更新 UI

关键结论：

  • 谁来触发事件？ → 你（原生），因为状态变化发生在原生
  • trust-min 做什么？ → 只提供 .on() 和 .emit() 容器，不关心何时触发
  • DApp 做什么？ → 只需要注册监听，等钱包通知

常见事件谁触发：

事件 触发时机 由谁触发
connect 连接成功 原生（你）
disconnect 断开连接 原生（你）
chainChanged 用户切换网络 原生（你）
accountsChanged 用户切换账户 原生（你）

三、ETH 转账完整示例

使用 useSendTransaction Hook 发送 ETH：

// hooks/useTransferETH.ts
import { useSendTransaction, useWaitForTransactionReceipt } from 'wagmi';
import { parseEther } from 'viem';

export interface UseTransferETHParams {
  to: string;        // 接收地址
  amount: string;  // 转账金额（单位 ETH）
}

export function useTransferETH({ to, amount }: UseTransferETHParams) {
  // sendTransaction 会弹出钱包确认
  const {
    data: txHash,
    error,
    isPending,
    sendTransaction
  } = useSendTransaction({
    to: to as `0x${string}`,
    value: parseEther(amount || '0'),
  });

  // 等待交易上链确认
  const {
    data: receipt,
    isLoading: isConfirming,
    isSuccess: isConfirmed
  } = useWaitForTransactionReceipt({
    hash: txHash,
  });

  return {
    sendTransaction,
    txHash,
    isPending,
    isConfirming,
    isConfirmed,
    receipt,
    error
  };
}

    sendTransaction,
    isPending,
    isConfirming,
    isConfirmed,
    txHash,
    receipt
  } = useTransferETH({ to, amount });

  return (
    <div>
      <input
        placeholder="接收地址"
        value={to}
        onChange={(e) => setTo(e.target.value)}
      />
      <input
        type="number"
        placeholder="金额 (ETH)"
        value={amount}
        onChange={(e) => setAmount(e.target.value)}
      />

      <button
        onClick={() => sendTransaction?.()}
        disabled={isPending || !to || !amount}
      >
        {isPending ? '等待确认...' : '发送 ETH'}
      </button>

      {txHash && (
        <div>
          交易哈希: {txHash}
          {isConfirming && <div>等待上链...</div>}
          {isConfirmed && receipt?.status === 'success' && (
            <div>✅ 转账成功！</div>
          )}
        </div>
      )}
    </div>
  );
}

五、合约读操作（查询数据）

使用 useReadContract Hook 查询合约只读数据：

// hooks/useERC20Balance.ts
import { useReadContract } from 'wagmi';
import { erc20Abi, formatUnits } from 'viem';

export function useERC20Balance(
  tokenAddress: string,
  ownerAddress: string | undefined,
  decimals: number = 18
) {
  const { data: balance, ...rest } = useReadContract({
    address: tokenAddress as `0x${string}`,
    abi: erc20Abi,
    functionName: 'balanceOf',
    args: ownerAddress ? [ownerAddress as `0x${string}`] : undefined,
    // 只有当 ownerAddress 存在才发起查询
    query: {
      enabled: !!ownerAddress
    }
  });

  // 格式化余额为可读字符串
  const formattedBalance = balance
    ? formatUnits(balance as bigint, decimals)
    : '0';

  return {
    balance,
    formattedBalance,
    ...rest
  };
}

七、等待交易确认完整流程

wagmi 处理交易确认非常简洁，完整流程：

export function TransactionButton() {
  // 1. 发送交易 → 等待用户在钱包签名
  const { sendTransaction, data: txHash, isPending } = useSendTransaction({...});

  // 2. 交易已发送 → 等待区块确认
  const {
    isLoading: isConfirming,
    isSuccess: isConfirmed,
    data: receipt
  } = useWaitForTransactionReceipt({
    hash: txHash,
    confirmations: 1, // 等待 1 个区块确认
  });

  // 3. 根据状态展示不同 UI
  if (isPending) {
    return <button disabled>请在钱包中确认...</button>;
  }
  if (isConfirming) {
    return <button disabled>交易打包中...</button>;
  }
  if (isConfirmed && receipt?.status === 'success') {
    return <button>✅ 交易成功！</button>;
  }

  return <button onClick={() => sendTransaction?.()}>
    发送交易
  </button>;
}
